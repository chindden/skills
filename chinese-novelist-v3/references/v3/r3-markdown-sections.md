# R3 · 核心契约与滚动卷纲 Markdown 分区协议（P0-02）

> **范围**：用于 R3 实验项目；**不适用于旧 R2**。本协议只定义文本切片、校验与指纹生成。卷级审批、正文写作授权、快照 Diff 属于后续 P0 项目。

## 1. 三份规划 Markdown 的标准结构

R3 明确要求固定且唯一的 H1 作品文件标题，以及两个按顺序出现的 H2 分区标记。结构示意：

`00-人物档案.md`

```md
# 人物档案
## 核心人设
主角的核心欲望、不可逆命运基准、关键关系及约束。
## 动态状态与远期弧线
未来可能发生的关系变化及随正文演化的设想。
```

`01-大纲.md`

```md
# 故事大纲
## 核心契约
读者承诺、世界/金手指硬规则、关键因果和必要的终局条件。
完整剧透故事方向可以保留，但**不**将非必要远期桥段搬入冻结区。
### 核心机制
可以使用三级及以下标题组织核心契约内部内容。
## 滚动卷纲
### 第1卷
卷一当前详细规划，下面可使用四级及以下标题拆故事弧。
### 第2卷
尚未锁定的未来卷概要，可以调整。
### 第3卷
远期路标，可以调整。
```

`03-文风基准.md`

```md
# 文风基准
## 文风指纹
稳定的叙事声线、视角原则和示范文本。
## 本书校准段落
随连续写作追加的实际文风校准。
```

以上 H1 只保留一处，两个分区 H2 必须原样出现，不接受其他 H2。01 的 `### 第1卷`、`### 第2卷`……是滚动区**唯一允许的 H3**，卷号从 1 连续递增；卷内场景/弧使用 H4 及以下层级。卷标题本身稳定，其具体可读名字请写在其正文内。

## 2. 冻结边界定义

- 每份文件的 **core** 切片：从文件开头（含 H1 标题）至滚动区 H2 标记之前。包含核心 H2 及全部核心内容。
- **rolling** 切片：从滚动区 H2 标记至文件结束。
- `01-大纲.md` 中每卷指纹：从该卷 H3 起至下一卷 H3（不含）或文件结束。
- 实现按原 UTF-8 文本计算 SHA-256；保留原始换行形式，`CRLF` 与 `LF` 哈希不同。不要偷偷做归一化。
- 当前 P0-02 仅输出上述指纹及分区结构；**尚未绑定已批准核心/卷级检查点，也不能据此授权写作**。P0-04/P0-05 才会增加审核证据与批准绑定。

## 3. 严格拒绝的输入

- 核心或滚动锚点缺失、重复、拼写变形或顺序错误。
- H1 缺失、重复，或 H1 之前存在非空说明文字。
- 任何多余 H2，任何卷号缺失/重复/乱序，卷区没有有效内容，滚动区卷一之前出现游离段落。
- 未闭合的 Markdown 围栏代码块。
- 原始 HTML 注释，包括隐藏标题；用于避免不同 Markdown 解析器对结构边界产生分歧。
- 通过目录符号链接指向项目目录外的规划文件。

围栏代码块中的假标题不会被识别为分区；改变有效 H1 标题会改变核心指纹。即便把核心段落挪到滚动区，也会因核心切片变化而改变核心指纹。**解析器不具备识别文学重要性或自动认定某项远期剧情是否应当锁定的能力**，这仍须由规划与编辑审核。

## 4. 给 Gemini 的安全工程试跑命令

在 **R3 独立实验项目** 内准备上述三份 Markdown、`02-写作计划.json`，先显式启用 R3：

```sh
node scripts/init_v3_state.mjs <实验项目目录> --enable-r3 --json
node scripts/r3_plan_sections.mjs <实验项目目录> --json
```

预期输出：`status: ready`、各文件的 `coreSha256`、卷级 `sha256` 与 `literaryStatus: UNVERIFIED`。若存在解析错误应输出 `status: error` 与明确错误码，退出码 2。

接着**只改第二卷或第三卷**，重跑解析器：核心哈希及第一卷哈希应不变；修改核心承诺后，核心哈希应改变。此处用于验证分区能力，**不代表修改任何已经获作者批准的卷**。

此阶段 `v3_gate.mjs` 对显式启用 R3 的项目继续返回 `R3_GATE_NOT_READY`，直至独立 R3 审核与授权门禁开发完成。不得借用旧 R2 的批准记录放行。
