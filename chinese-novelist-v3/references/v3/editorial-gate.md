# 独立编辑、逐章复核与前三章停审协议

## 1. 目标与边界
写作 Agent 与审稿 Agent 的任务应分开。具备独立子 Agent 时，用新的执行上下文审稿；若环境只有一个上下文，则明确标注“同模型自审，未实现隔离”，不得假称盲审。
审稿不以“毒舌”“禁止夸奖”为目标。应识别好在哪里、差在哪里，以及是否值得目标读者继续阅读。

## R2 双层独立审稿

- **每章**：不同真实执行上下文的审核 Agent 只读本章与必要前文，查时间与数量、人物首次出场、身份识别、知情来源、因果和场景切换等确凿缺陷。合理悬念和有意留白不算错误；无证据则 PASS，不要求全文润色。
- **每三章**：第 3 章复用现有 Pilot 审稿与作者确认；第 6、9、12……章额外连读最近三章，评价人物变化、节奏、情节推进、伏笔兑现、机制重复和追读体验。后续三章审核无需每次请作者签字。
- **职责隔离**：作者只定向修改经证实的片段，审核者只提供问题和证据，不直接改稿。任何正文修订会使所对应审核版本失效，必须重新准备并复核。
- **执行边界**：同一基础模型的不同真实上下文可承担写作和审核；不同 runId/contextId 字段只能验证声明不同，不能证明真实代理隔离，必须保存宿主任务日志。不能创建独立上下文时停工，不得伪造。
- **门禁**：前章独审未通过不能写下一章；第 6、9、12……章整体审稿未通过不能继续；现有每五章账本审计照常保留。

## 2. 审稿输入与最小信息原则
编辑只接收：
- 当前核查范围内章节（单章、三章或 Pilot）的**不可变版本**与 SHA-256
- 人物/世界规则与目标受众
- 独立审稿要求、必要的客观核验资料
不提供作者的私有推理、自评分、预期高分或提前写好的辩解。
共享文件系统不等于访问控制；若子 Agent 能看全部目录，需限制其工作范围并记录实际输入，不能宣称技术上的文件权限隔离。

## 3. 逐项审查
1. **创意兑现**：独特设定是否引出必须在本故事发生的事件。
2. **人物活人感**：目标清楚；性格缺陷导致后果；配角有私心；行为可从其所知与情绪解释。
3. **逻辑与现实细节**：因果闭合、人物知情边界、物理/技术细节与资源台账；专业质疑附核验依据或标“待核实”。
4. **节奏与追读**：开篇承诺、情绪变化、人物牵挂、章节之间的必要期待；不能靠结尾虚假炸点或机械误会。
5. **表达与语言**：角色声音、对话潜台词、视觉角度、重复解释、机械场景扫描、二阶 AI 味；禁止按词表替代语境判断。
6. **新鲜感**：故事机制是否重复；同类冲突有没有不同决策代价或局势变化。

## 4. 缺陷报告协议
保存为 `reviews/pilot-revision-N.md`。每条缺陷包含：
- `ID` 与严重性：`BLOCKER`、`MAJOR`、`MINOR`
- 原文定位：章号、明确片段或稳定段落标识
- 可以直接从文本证明的事实
- 对读者体验的实际影响
- 修订建议（尽量最小必要修改）
- 核验状态：已证实／有争议／待查
另外写保留的优秀桥段和优点，不要在返工时误删。

## 5. 去留决定
- **reject**：存在未解决 BLOCKER；作者返工并重新独立审查。
- **revise**：有明确重大问题，交付定向改稿，再审。
- **pass_candidate**：未发现阻断问题，重大问题得到修正或有记录地接受。

只有审稿候选通过且作者明确批准开篇，才能将计划里的 `v3.pilotGate.status` 记为 `passed`。
审稿员不得自行代签作者同意；作者拒绝或要求改则保持 blocked。

## 6. 审稿版本绑定
审稿报告应明确绑定所审正文 SHA-256。正文改动后，旧报告自动失效，需至少进行变更范围复核；涉及人物行为、线索或因果调整时应重新评估全三章。
当前 `scripts/v3_gate.mjs` 只做结构化状态与文件门禁，不对报告文学质量做真实性判断。不得把程序返回 0 宣称为“编辑客观确认精品”。

## 7. 用户放行前的呈现
向用户提交前三章、审稿报告摘要、已修复/待接受问题、是否达到进入第 4 章条件。缺陷严重但用户要求继续时，除非修改了既有事实导致不可继续，否则可记录明示接受的非阻断风险；BLOCKER 仍须修复或调整故事架构。
