# Chinese Novelist V3

目标：帮助作者产出**有辨识度、人物鲜活、逻辑可信且值得追读**的作品。流程和评分是提高质量的手段，不是精品保证。

## 执行优先级
1. 先读本文件及 [V3 总流程](references/v3/workflow.md)。所有 V3 门禁、状态和用户确认要求优先于原版 `references/flows/` 中的“自动写完整书”指令。原版保留为技法和工具底座，**不要运行与 V3 冲突的旧流程**。
2. 根据任务按需读取 [创意竞标](references/v3/creative-lab.md)、[题材与架构](references/v3/story-architecture.md)、[独立审稿](references/v3/editorial-gate.md)、[状态与备份](references/v3/state-and-backup.md)。
3. 原版人物、对话、章节、悬念和文风指南仍可按需读取。V2 的反套路、资源限制、对话博弈与二阶 AI 味建议已吸收到 V3 参考文档；旧版固定爽点配额并非通用硬约束。

## 六阶段主流程
1. **创意竞标**：默认 3 个核心引擎不同的候选；对既定创意做 3 个不同重构方向；比较创意不可替代性、人物情绪驱动和长线可持续性。用户决定最终选项。
2. **故事架构**：全书→分卷→故事弧→章节，细化未来近端、远端保持弹性；保存角色与关系状态、规则、资源、线索、伏笔、文风指纹。
3. **前三章试写**：按题材适配开篇，不机械套用玄幻“危机／金手指／反杀”公式。逐章串行并更新项目状态。
4. **强制停审**：第 3 章后禁止启动第 4 章，直到独立审稿、缺陷返工、复审与用户确认均有记录。支持隔离子 Agent；不支持时不得谎称独立审稿。
5. **分卷连载**：相邻正文优先串行；每章检查事实、因果、人物状态与字数，每 5 章审计机制重复、人物弧线及悬念兑现。
6. **快照备份**：每个已完成章可生成完整 ZIP 快照、SHA-256 清单，上传外部存储并回读验证；仅验证成功才能标记备份有效。

## 不可跳过的可执行门禁
- 在**创建第 4 章及其后正文前**运行：
  `node scripts/v3_gate.mjs <项目目录> --chapter <章号> --json`
  非 0 退出码立即停止，不得因“用户希望快速写完”绕开。
- 工程校验继续执行原版 `scripts/validate_project.mjs`；它只验证状态和字数，**不代表文学审稿通过**。
- 独立审稿报告必须有原文证据、严重程度和明确返工点；缺陷未修复不得宣称审核通过。
- 生产小说正文时的项目字段和门禁规则见 [状态与备份](references/v3/state-and-backup.md)。
- 如果无法真实操作目录、脚本或子 Agent，明确说明降级能力并保留交付记录；**不得伪造文件、执行日志、审核人或备份**。

## 质量原则
- 硬规则：因果、已确立事实、信息边界、重要物品及资源状态不能自相矛盾。
- 软策略：爽点频率、章末钩子、对话篇幅、视角密度、人物理性程度视题材与情境确定；真实人物允许可信的非理性、犹疑和失误。
- 以真实读者盲评和作品对照为最终质量证据；不以自评分或字数判定精品。
